## System Overview

This repository packages three third-party pieces into one container image that keeps TLS
certificates fresh without operator interaction. It clones the
[dehydrated](https://github.com/dehydrated-io/dehydrated) ACME client and the
[letsencrypt-cloudflare-hook](https://github.com/SeattleDevs/letsencrypt-cloudflare-hook) DNS-01
hook at build time, adds a bash script that wires them together, and installs that script into
Alpine's `periodic/daily` directory so busybox cron runs it at 02:00 container-local time.

The consumer is an operator who owns DNS for one or more domains in CloudFlare and needs Let's
Encrypt certificates on disk for another service to read. They run one `docker create` with a
CloudFlare API token and volumes, start the container, and from then on certificates are issued at
first start and renewed once within 32 days of expiry. Certificates land in `/dehydrated/certs`,
owned by a configurable user and group, with public material world-readable and private keys
readable only by that group.

Nothing in the image is version-pinned: it tracks the default branch of both upstream projects and
the floating `python:alpine` base. That is deliberate, and the reason a watcher workflow exists.
Every 12 hours it compares the two upstream commits and the base image digest against what was
last published, and rebuilds only on change, recording the result. This replaced a blind weekly
rebuild that had no record of what it produced and that GitHub silently disabled after 60 days of
repository inactivity, freezing the published image for roughly 4.5 months.

### Why these units

A container image repository fits no catalog entry exactly: the image is the product, and the
Dockerfile is closer to an infrastructure module than an application. The unit chosen is therefore
**one document per artifact an outside party interacts with**: the image an operator pulls, the
configuration contract they satisfy, the job that runs on their behalf, and each pipeline that
produces or guards the artifact.

## Permission Model

No application-level authentication or role model exists: nothing here serves requests.

| Context | Who is authorized | How | Enforcement |
|---|---|---|---|
| CloudFlare DNS | A zone-scoped API token, or a legacy global key | Passed through the environment to the hook | Enforced by CloudFlare. Presence checked by the renewal preflight. See [BL-CFG-005](../BUSINESS-LOGIC.md#bl-cfg-005) |
| ACME account | An account key generated on first run | `-c --accept-terms` | See [BL-RENEW-009](../BUSINESS-LOGIC.md#bl-renew-009) |
| Certificate public material | Every user on the host and in containers sharing the volume | Recursive `ugo+r` | See [BL-CERT-005](../BUSINESS-LOGIC.md#bl-cert-005) |
| Certificate private keys | Only `PUID` and members of `PGID` | `chmod o-rwx` on `privkey*` | See [BL-CERT-004](../BUSINESS-LOGIC.md#bl-cert-004) |
| ACME account key | Root only | Left at upstream's `0600` | See [BL-CERT-005](../BUSINESS-LOGIC.md#bl-cert-005) |
| Docker Hub publish | The Actions runner | `DOCKER_USERNAME` / `DOCKER_PASSWORD` secrets | See [BL-CI-004](../BUSINESS-LOGIC.md#bl-ci-004) |
| Merging dependency updates | Dependabot, gated by the build check | `gh pr merge --auto` behind a required status check | See [BL-CI-011](../BUSINESS-LOGIC.md#bl-ci-011) |

The container runs as root: there is no `USER` directive, which is what allows the `chown`.

## Cross-cutting Notes

- **Nothing is pinned, on purpose.** The base image and both clones float; the watcher rebuilds on
  change and records what it built. Pinning was considered and rejected: dehydrated's latest
  release is 16 months older than its default branch, so pinning would have frozen the image far
  behind what is shipped today.
- **Failure is soft and observable.** The renewal script exits 0 in normal operation; failures
  surface through the status file and the Docker health status.
- **Both persistent paths are volumes.** `/dehydrated/certs` and `/dehydrated/accounts`.
- **Times:** CI cron expressions are UTC; the in-container daily job is 02:00 container-local.
- **All configuration is environment plus mounts.** No config file, no flags, no runtime API.
